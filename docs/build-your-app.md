# 내 앱 만들기 — 직접 코딩 · AI 로 생성

이 문서는 **여러분의 업무(꽃 배달 · 대리운전 · 예약 · 상담 …)에 맞는 DVG 음성 앱**을 처음부터 끝까지 만드는 순서입니다.
코딩에 익숙하면 [길 B](#길-b--예제를-고쳐-직접-코딩), AI 도구에 맡기려면 [길 C](#길-c--ai-로-만들기)로 가십시오. 묻는 것만 바꾸면 되는 업무는 [길 A](#길-a--시나리오-파일만-쓰기-코딩-거의-없음)가 가장 빠릅니다.

```
① 명세서 채우기 ─▶ ② 길 고르기(A·B·C) ─▶ ③ 로컬 점검(키 없이) ─▶ ④ 운영사 등록 ─▶ ⑤ simulate 시험 ─▶ ⑥ 배포 ─▶ ⑦ 실통화
```

## 1. 명세서부터 — 모든 길의 출발점

[앱 명세서 양식](app-spec-template.md)을 복사해 채우십시오. 무엇을 묻고, 어떻게 복창하고, 어디에 등록하고, 언제 사람에게 넘기는지가 다 들어갑니다.

⭐ **명세서가 곧 앱의 품질입니다.** AI 에게 맡길 때 특히 그렇습니다 — AI 는 명세서에 없는 업무 규칙을 **그럴듯하게 지어냅니다.**
빈칸은 «모름» 이라고 적어 두면 AI 가 지어내지 않고 물어봅니다.

## 2. 길 고르기

| 길 | 이럴 때 | 해야 하는 일 | 필요한 실력 |
|---|---|---|---|
| **A. 시나리오 파일만** | 칸을 순서대로 묻고 → 복창하고 → 등록하면 끝나는 업무 | JSON 파일 하나 + 등록 함수 한 군데 | JSON · API 호출 한 번 |
| **B. 예제를 고쳐 직접 코딩** | 고객 조회·분기·문자 안내 등 흐름이 업무마다 다르다 | 같은 언어 예제를 복사해 대화 부분 수정 | 그 언어로 웹 서버를 다뤄 봤다 |
| **C. AI 로 만들기** | B 와 같은데 코딩을 AI 에게 맡긴다 | 명세서 + 프롬프트 → 생성 → 점검 → 고치기 반복 | 결과를 읽고 점검을 돌릴 수 있다 |

## 길 A — 시나리오 파일만 쓰기 (코딩 거의 없음)

[`examples/python/slot_app.py`](../examples/python/slot_app.py) 는 **시나리오 JSON 을 읽어 대화를 진행하는 엔진**입니다.
대화 규칙(다시 물을 때 질문 바꾸기 · 두 번 실패하면 사람에게 · 마지막 전체 복창 · 주소 좁히기)은 엔진에 이미 들어 있습니다.

1. 가장 가까운 시나리오([꽃 배달](../examples/python/scenarios/flower.json) · [대리운전](../examples/python/scenarios/driver.json) · [음식 배달](../examples/python/scenarios/food.json))를 복사해 명세서 §2 의 칸으로 바꿉니다. 아래는 꽃 배달 시나리오입니다.

   ```json
   {
     "name": "꽃 배달",
     "greeting": "꽃 배달 주문을 도와드리겠습니다.",
     "slots": [
       {"key": "dest", "type": "address", "label": "배달지", "readback": "배달지",
        "ask": "꽃을 어디로 보내 드릴까요?",
        "again": "제가 잘 못 들었습니다. 받으실 곳의 구와 동을 말씀해 주세요."},
       {"key": "product", "type": "choice", "readback": "상품", "choices": ["꽃다발", "꽃바구니", "화환"],
        "ask": "꽃다발. 꽃바구니. 화환. 어느 쪽으로 보내 드릴까요?",
        "again": "제가 잘 못 들었습니다. 꽃다발이면 「꽃다발」. 꽃바구니면 「꽃바구니」. 화환이면 「화환」."}
     ],
     "done": "주문이 접수되었습니다. 감사합니다."
   }
   ```

   | 칸 | 뜻 |
   |---|---|
   | `type` | `address`(주소) · `choice`(선택 2~6개) · `text`(자유) |
   | `ask` · `again` | 첫 질문 · 다시 물을 때 — **둘은 달라야 합니다**(같으면 엔진이 시작을 거부합니다) |
   | `readback` | 마지막 복창에서 이 칸 앞에 붙는 말(「상품 꽃바구니.」) |
   | `label` | 주소 칸을 좁혀 물을 때 부를 이름(10자 이하) |

2. 검사합니다 — 틀린 시나리오로는 통화를 받지 않게 시작할 때 거릅니다.

   ```bash
   cd examples/python && python3 slot_app.py --check scenarios/my_flower.json
   ```

3. `register_order()` 안에 업무 시스템 API 호출을 넣습니다(명세서 §3). **재시도하지 마십시오** — 실패하거나 결과를 모르면 `False` 를 돌려주면 엔진이 사람에게 넘깁니다.
4. [3. 로컬 점검](#3-로컬-점검--키-없이-내-컴퓨터에서)으로 갑니다.

⚠️ 길 A 로 안 되는 것: 발신번호로 고객 조회 후 질문 건너뛰기 · 문자 안내 · 칸마다 다른 분기. 이것이 필요하면 길 B·C 로 가되 **엔진을 고쳐 쓰는 것**부터 생각하십시오.

## 길 B — 예제를 고쳐 직접 코딩

1. **언어를 고르고 예제를 복사합니다** — [Python](../examples/python/order_app.py) · [Node.js](../examples/node/order_app.mjs) · [Go](../examples/go/main.go) · [Java](../examples/java/) · [Rust](../examples/rust/). 다섯 예제는 같은 일을 합니다.
2. **건드리지 않을 곳** — 서명 확인 함수(`verify_dvg` 등) · 연결 받기 · 메시지 받기(`recv`). 이것들은 [시험 벡터](../conformance/vector.json)로 검증된 코드입니다.
3. **고칠 곳** — 대화를 이끄는 함수(예제의 `handler`) 하나와 등록 함수(`register_order`) 하나입니다.
4. 대화의 뼈대는 언제나 같습니다.

   ```text
   setup 받기
     └ (발신번호 제공이면) 업무 시스템에서 고객 조회 — 10초 넘으면 먼저 say 로 시간을 번다
   첫 인사(say)
   칸마다:
     ask(첫 질문) → prompt
       못 얻으면 ask(다른 질문) → prompt
       또 못 얻으면 transfer(note: 모은 칸 + 못 들은 칸) 하고 끝
   전체 복창 ask(choices: 네/아니요)
     「네」  → simulated·chat 이 아니면 등록(재시도 없음) → 성공이면 hangup(끝 인사) · 실패·모름이면 transfer
     그 밖   → transfer
   end 를 받거나 연결이 닫히면 조용히 끝낸다
   ```

5. 메시지 하나 받을 때마다 지시 하나 — 이 규칙만 지키면 어떤 흐름이든 됩니다. 모든 메시지와 필드는 [계약 §3](voice-relay-v1.md#3-메시지).
6. 지켜야 할 규칙 전부는 [AGENTS.md](../AGENTS.md) 에 표로 있습니다 — 직접 코딩할 때도 그 표가 검토 기준입니다.

## 길 C — AI 로 만들기

이 저장소에는 [AGENTS.md](../AGENTS.md)(AI 코딩 도구가 먼저 읽는 규칙)가 있습니다. Claude Code · Codex · Cursor 처럼 **저장소를 열고 작업하는 도구**는
이 파일을 스스로 읽습니다. 웹 채팅(ChatGPT·Claude 웹)이라면 파일 내용을 직접 붙여 넣어야 합니다.

### C-1. 준비물

| 준비물 | 어디서 |
|---|---|
| 채운 명세서 | [1. 명세서](#1-명세서부터--모든-길의-출발점) |
| 이 저장소 | `git clone https://github.com/OLSSOO-Inc/dvg-apps.git` |
| 업무 시스템 API 문서 | 여러분 회사 것 — 엔드포인트·필드·인증·오류 응답 |
| 테스트용 서명 비밀 | 아무 문자열(예: `test-secret`) — 운영사에서 받은 진짜 값은 AI 에게 **주지 마십시오** |

🔴 **진짜 키·비밀번호·서명 비밀을 프롬프트에 붙여 넣지 마십시오.** AI 도구의 기록에 남습니다. 코드는 환경변수에서 읽게 만들고, 값은 실행할 때 여러분이 넣습니다.

### C-2. 첫 프롬프트 — 저장소를 여는 AI 도구(Claude Code · Codex · Cursor)

저장소 폴더에서 도구를 열고, 명세서를 `my-app-spec.md` 로 저장한 뒤 아래를 붙여 넣습니다(`< >` 를 바꾸십시오).

```text
이 저장소는 DVG 음성 앱 개발 키트다. 먼저 AGENTS.md 와 docs/voice-relay-v1.md 를 끝까지 읽어라.

my-app-spec.md 의 명세대로 음성 앱을 만들어라.
- 언어: <Python>. examples/<python>/order_app.py 를 복사해 apps/<my-app>/ 에 두고 시작해라.
  서명 확인·연결 받기·메시지 받기 코드는 예제 것을 그대로 쓴다.
- 업무 시스템 API 는 <docs/my-api.md 또는 아래 설명>이다. 키는 환경변수 <MY_API_KEY> 에서 읽는다.
- 명세서에 없는 업무 규칙은 지어내지 말고 나에게 물어라.

다 만들면 아래를 실제로 돌리고 결과를 그대로 보여 줘라.
1. conformance/vector.json 을 쓰는 서명 단위 시험
2. 앱을 띄운 뒤 tools/local_dvg.py 로 명세서 §7 의 대화 예 전부(종료 코드 0 이어야 한다)
3. 돌리지 못한 시험이 있으면 "못 돌렸다" 고 적어라.
```

### C-3. 첫 프롬프트 — 웹 채팅(ChatGPT · Claude 웹 등)

웹 채팅은 저장소를 읽지 못합니다. 아래 **세 파일의 내용**을 차례로 붙여 넣거나 첨부한 뒤 프롬프트를 보내십시오.

1. [`AGENTS.md`](../AGENTS.md)
2. [`docs/voice-relay-v1.md`](voice-relay-v1.md)
3. 고른 언어의 예제 파일 하나(예: [`examples/python/order_app.py`](../examples/python/order_app.py))
4. 채운 명세서

```text
위의 AGENTS.md 는 반드시 지킬 규칙, voice-relay-v1.md 는 DVG 와 주고받는 계약, order_app.py 는 동작하는 예제,
마지막은 내 앱의 명세서다.

예제를 바탕으로 명세서대로 동작하는 앱 전체 코드를 파일 하나로 만들어라.
- 서명 확인·연결 받기·메시지 받기 코드는 예제 것을 그대로 둔다.
- 계약에 없는 메시지나 필드를 만들지 마라.
- 키는 환경변수에서 읽는다.
- 명세서에 없는 업무 규칙이 필요하면 코드를 쓰기 전에 나에게 질문해라.
코드 아래에 AGENTS.md §1·§2 의 규칙을 하나씩 짚으며 어디서 지켰는지 적어라.
```

받은 코드는 저장소의 `apps/<내앱>/` 에 저장하고 [3. 로컬 점검](#3-로컬-점검--키-없이-내-컴퓨터에서)을 **여러분이 직접** 돌리십시오. 웹 채팅 AI 는 코드를 실행해 보지 못합니다.

### C-4. 고칠 때 — 점검 결과를 그대로 돌려준다

로컬 점검이나 `simulate` 에서 문제가 나오면 **출력을 그대로** 붙여 넣는 것이 가장 빠릅니다.

```text
tools/local_dvg.py 를 돌렸더니 아래처럼 나왔다. 원인을 설명하고 고쳐라.
고친 뒤 같은 대화로 다시 돌려 종료 코드 0 이 나오는지 확인해라.

<출력 붙여 넣기>
```

말투만 고칠 때:

```text
아래 문장들이 전화에서 붙어 들린다. AGENTS.md §2 말투 규칙에 맞게 고쳐라.
선택지는 낱말마다 마침표, 물음은 문장 끝에 한 번, 다시 물을 때는 첫 질문과 다른 문장.
<문장 붙여 넣기>
```

### C-5. 검토 프롬프트 — 다른 AI(또는 같은 AI 의 새 대화)에게

만든 AI 가 스스로 검토하면 자기 실수를 잘 못 봅니다. **새 대화**에서 검토만 시키십시오.

```text
AGENTS.md 의 규칙표(§1 1~12번, §2 말투)를 기준으로 아래 코드를 검토해라.
규칙마다 "지킴 / 어김 / 판단 불가" 를 코드 줄 번호와 함께 표로 적어라.
특히 다음을 꼭 봐라:
- 메시지 하나에 지시가 정확히 하나인가(지시 둘을 연달아 보내는 곳이 없는가)
- 주문 등록 API 를 재시도하는 곳이 있는가
- simulated / channel=chat 일 때 실제 주문을 막는가
- 키·전화번호·발화 원문을 로그에 찍는가
- 같은 질문 문장을 두 번 이상 보내는 경로가 있는가
<코드 붙여 넣기>
```

### C-6. AI 가 자주 하는 실수 — 받은 코드에서 먼저 찾아볼 것

| 실수 | 찾는 법 | 고친 모양 |
|---|---|---|
| 지시를 **연달아 두 개** 보낸다(`say` 뒤 응답을 안 기다리고 `ask`) | `send` 가 `recv` 없이 이어지는 곳 | 보낼 때마다 다음 메시지를 받는다 |
| 주문 등록을 **재시도**한다(`retry`·`for attempt in range`) | 등록 함수 안의 반복문·재시도 라이브러리 | 한 번만 부르고 실패·모름이면 `transfer` |
| 서명 확인을 **연결 뒤**에 하거나 빼먹는다 | 업그레이드 전 훅(`process_request` 등) | 예제 코드를 그대로 |
| 계약에 없는 필드를 쓴다(`transfer.to` · `ask.hints` · `say.voice`) | 계약 §3-3 표와 대조 | 지운다 — 필요하면 운영사에 문의 |
| 주소를 **직접 파싱**한다(시·도 목록·정규식) | 행정구역 이름이 든 상수 | `expect:"address"` 로 DVG 에 맡긴다 |
| 선택지를 **쉼표·「~인지」** 로 나열한다 | 질문 문자열의 `,`·`인지` | 낱말마다 마침표 |
| 다시 물을 때 **같은 문장**을 쓴다 | 같은 문자열이 반복문 안에서 다시 나감 | 둘째 문장을 따로 둔다 |
| `end`·연결 닫힘에서 **예외로 죽는다** | `recv` 주변의 예외 처리 | 그 통화만 조용히 끝낸다 |
| 키·전화번호를 `print`/`log` 한다 | 로그 줄 | 건수·결과 코드만 남긴다 |
| 업무 API 토큰을 **통화마다 새로 받는다** | 통화 처리 함수 안의 로그인 호출 | 캐시 — [외부 API 자격증명 §3](external-api-credentials.md#3-토큰-재사용-규칙) |

## 3. 로컬 점검 — 키 없이 내 컴퓨터에서

[`tools/local_dvg.py`](../tools/local_dvg.py) 는 DVG 를 흉내 내 **서명 헤더를 붙여 앱에 연결**하고, 여러분이 적은 말을 발신자 말로 보냅니다.

```bash
pip install -r examples/python/requirements.txt
```

창 하나에서 앱을 띄웁니다(예: Python 예제).

```bash
cd examples/python && DVG_SIGNING_SECRET=test-secret python3 order_app.py
```

다른 창에서 대화를 돌립니다. 빈 문자열(`""`)은 무응답입니다.

```bash
DVG_SIGNING_SECRET=test-secret python3 tools/local_dvg.py "강남역" "" "서초동" "착불" "네"
```

```text
🤖 AI(질문) 어디에서 보내시나요?
🙋 발신자 강남역
🤖 AI(질문) 어디로 보내시나요?
🙋 발신자 (무응답)
🤖 AI(질문) 제가 잘 못 들었습니다. 물건을 받으실 곳을 말씀해 주세요.
…
결말: completed · 지시 6회 · 위반 0건 · 말투 경고 0건
```

| 표시 | 뜻 |
|---|---|
| `❌` | 계약 위반 — 실통화에서는 사람에게 넘어가거나 오류가 난다(10초 초과 · 잘못된 선택지 · 모르는 메시지 · 번호를 넣은 `transfer` · 긴 문자 등) |
| `⚠️` | 말투 경고 — 예시를 쉼표로 이었다 |
| 종료 코드 | `0` 위반·경고 없음 · `1` 있음 · `2` 연결 실패(앱이 안 떴거나 서명 비밀이 다름) |

발화를 파일로 두면 반복하기 쉽습니다 — 명세서 §7 의 대화를 JSON 배열로 저장하십시오.

```bash
DVG_SIGNING_SECRET=test-secret python3 tools/local_dvg.py --file calls/normal.json
```

⚠️ **흉내는 진짜가 아닙니다.** 주소 풀이·좁히기·생년월일·전화번호 판정·선택지 초성 추정은 하지 않습니다(주소는 «풀이를 쓸 수 없는 설치» 로 응답합니다).
형식과 흐름을 잡는 도구이고, **마지막 확인은 5. simulate** 입니다.

## 4. 운영사 등록

운영사에 요청할 것은 [README 의 역할 표](../README.md#누가-무엇을-하나--운영사관리자--앱-개발사) 아래 «운영사에 요청할 것 목록» 에 있습니다.
명세서 §5·§8 에서 «운영사에 요청» 이라고 적은 칸을 그대로 보내면 됩니다. 앱 키와 서명 비밀은 **한 번만** 보여 주니 바로 비밀 저장소에 넣으십시오.

키를 받으면 음성인식 힌트 낱말(명세서 §6)·설정 항목(§5)·AI 고지 문구는 앱 키로 직접 넣습니다 — [시작하기 §4](getting-started.md#4-시험하기).

## 5. simulate — 운영사 DVG 로 전화 없이 시험

```bash
curl -sS -X POST -H "Authorization: Bearer $DVG_APP_KEY" -H 'Content-Type: application/json' -d '{"utterances":["신천동이요","서울이요","꽃바구니로 할게요","네"]}' "https://<DVG 주소>/api/v1/apps/self/simulate"
```

- 여기서는 **주소 좁히기·선택지 판정이 진짜**로 돕니다. 명세서 §7 의 대화를 전부 돌리십시오.
- AI 줄에 `toneWarning` 이 하나라도 있으면 그 문장을 고칩니다.
- 시험 통화는 `setup.simulated:true` 라 앱이 실제 주문을 만들지 않아야 합니다 — 여러분의 업무 시스템에 주문이 생기지 않았는지 확인하십시오.

## 7. 실통화 — 첫 주에 볼 것

| 볼 것 | 어디서 | 이상하면 |
|---|---|---|
| 결말 분포(완료 · 사람 연결 · 오류) | `GET /api/v1/apps/self/usage` | `app_error` 가 있으면 10초 초과·예외부터 |
| 대화 기록(운영사가 «기록 공유» 를 켰을 때) | `GET /api/v1/apps/self/diag` | 같은 칸에서 계속 넘어가면 질문 문장·힌트 낱말을 고친다 |
| 평균 통화 길이 | `usage` 의 `averages` | 길수록 비용 — 질문을 줄이고 복창을 짧게 |

실통화의 발화는 「강남역**이요**」·「어… 서초동」 처럼 군말이 붙어 옵니다. 시험에서 통과해도 첫 주는 기록을 읽어 보십시오.

## 체크리스트 — 올리기 전에

- [ ] 명세서의 빈칸이 없다(«모름» 칸은 운영사에 확인했다)
- [ ] 서명 시험 벡터 통과 · 틀린 비밀은 401
- [ ] `tools/local_dvg.py` 로 명세서 §7 의 대화 전부 종료 코드 0
- [ ] `simulate` 로 같은 대화 · `toneWarning` 0건 · 업무 시스템에 시험 주문이 생기지 않았다
- [ ] 주문 등록은 한 번만 · 실패·모름은 사람에게 · `simulated`·`chat` 이면 등록하지 않는다
- [ ] 키는 환경변수(비밀 저장소)에만 · 로그에 키·전화번호·발화 원문이 없다
- [ ] [시작하기 §5 체크리스트](getting-started.md#5-체크리스트)도 확인했다
