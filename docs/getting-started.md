# 시작하기 — DVG 음성 앱 만들기

## 0. 한눈에

1. **등록 받기** — DVG 운영사에 앱 id·연결 주소(`ws(s)://…`)를 알리면 **앱 키**와 **서명 비밀**을 한 번 받습니다. 함께 요청할 것은 [README 의 역할 표](../README.md#누가-무엇을-하나--운영사관리자--앱-개발사)에 있습니다.
2. **앱 띄우기** — 연결 주소에서 WebSocket 을 엽니다. [예제](../examples/)를 그대로 시작점으로 쓰면 됩니다.
3. **시험** — 전화 없이 [시험 API](#4-시험하기)로 대화를 끝까지 돌려 봅니다.
4. **설치** — 운영사가 주문 회사에 앱을 설치하면 그 회사로 오는 전화를 앱이 응대합니다.

## 1. 언어

아무 언어나 됩니다. 필요한 것은 ① WebSocket 서버 ② JSON ③ HMAC-SHA256 뿐입니다. 서명 구현이 맞는지는 [적합성 시험 벡터](../conformance/vector.json)로 확인하십시오. 예제는 [Python](../examples/python/) · [Node.js](../examples/node/) · [Go](../examples/go/) · [Java](../examples/java/) 네 가지이고 동작이 같습니다.

## 2. 어디에서 돌리나 — 다른 서버 / **DVG 와 같은 서버**

| 형태 | 연결 주소 예 | 맞는 경우 |
|---|---|---|
| **다른 서버** | `wss://app.example.com/dvg-relay` | 개발사가 자기 인프라에서 운영 · 여러 DVG 가 한 앱을 쓸 때 |
| **같은 서버**(DVG 와 한 대) | `ws://127.0.0.1:19999/relay` | 작은 고객 · 서버를 한 대로 끝내고 싶을 때 |

⚠️ 앱은 어느 경우든 **DVG 와 별개의 프로세스**로 돕니다 — 앱이 죽으면 그 앱이 맡은 통화만 사람에게 넘어갑니다.

### 2-1. 같은 서버 — DVG 가 띄우는 사이드카(DVG 1.4.16.262+)

운영사가 사이드카를 켜면 **DVG 가 앱 프로세스를 띄우고 지켜봅니다.** 앱 쪽에서 할 일은:

- 실행 파일 하나(`run`)를 운영사에 전달합니다 — 셸 스크립트·파이썬·Node·바이너리 무엇이든.
- 아래 환경변수를 읽습니다(예제 둘 다 이미 읽습니다):

| 이름 | 뜻 |
|---|---|
| `DVG_APP_ID` | 앱 id |
| `DVG_APP_SIGNING_SECRET` | 서명 비밀 — 키를 재발급하면 DVG 가 앱을 **자동으로 다시 시작**해 새 값을 넣습니다 |
| `DVG_APP_HOST` · `DVG_APP_PORT` · `DVG_APP_PATH` | 열어야 할 주소 |
| `DVG_APP_DATA_DIR` | 앱이 쓸 수 있는 디렉터리(재시작해도 남는다 · 이 밖에 쓸 수 있는 곳은 `/tmp` 뿐) |
| `DVG_API_BASE` | 앱 자기 조회 API 주소(루프백) |
| (운영사가 넣은 값) | 업무 시스템 자격증명 등 앱이 쓸 비밀 |

사이드카는 격리된 환경에서 돕니다 — 쓰기는 `DVG_APP_DATA_DIR`·`/tmp` 에만 되고, 앱 폴더 밖의 서버 파일은 읽을 수 없다고 생각하십시오. 메모리 등 자원 상한은 운영사가 정하므로 **필요한 메모리를 운영사에 알리십시오.** **앱은 `DVG_APP_DATA_DIR` 밖에 파일을 쓰지 않게** 만드십시오.

실서버 설치 순서(nginx·systemd·사이드카 파일 포함)는 [실서버 설치 퀵 가이드](deploy-quickstart.md)에 있습니다.

### 2-2. 여러 대로 돌리기(DVG 1.4.16.342+)

앱 인스턴스를 둘 이상 두는 방법은 둘입니다.

| 방법 | 운영사에 알릴 주소 | DVG 가 하는 일 |
|---|---|---|
| 앞에 부하 분산기(Cloud Run · nginx upstream 등) | 분산기 주소 **하나** | 그 주소로 붙는다 — 나누는 것은 분산기 |
| 분산기 없이 서버 여러 대 | 서버별 주소 **여러 개**(최대 5) | 운영사가 고른 방법으로 한 곳을 고른다 — **순서대로**(앞이 안 되면 벨 울리는 동안 다음) 또는 **한가한 곳 먼저**(이 DVG 가 붙은 통화가 가장 적은 곳). 연결에 실패한 주소는 잠시 뒤로 미룬다 |

- **통화 한 건은 처음부터 끝까지 인스턴스 하나**가 맡습니다(연결이 고정됩니다). 대화 상태는 그 인스턴스 메모리에 두면 됩니다.
- 통화 중에 그 인스턴스가 죽으면 그 통화는 다른 인스턴스로 옮겨지지 않고 **사람에게** 넘어갑니다. 다음 통화부터 살아 있는 곳으로 갑니다.
- 같은 통화를 두 인스턴스에 동시에 보내는 방식은 **없습니다** — 두 곳이 같은 통화에 지시하면 주문이 두 번 들어갑니다.
- 인스턴스끼리 **공유해야 하는 것**은 따로 챙기십시오: 업무 API 토큰([외부 API 자격증명 §4](external-api-credentials.md#4-앱을-여러-대로-돌릴-때하나뿐인-토큰-api)) ·
  고객 기억 같은 상태(로컬 파일은 인스턴스마다 따로입니다 — 업무 시스템이나 공유 저장소에 두십시오) · 중복 주문 방지(재시도 금지 또는 멱등 키).

## 3. 대화 규칙 — 이것만 지키면 됩니다

| 규칙 | 이유 |
|---|---|
| **DVG 메시지 하나에 지시 하나**(엄격한 요청·응답) | `setup`·`said`·`prompt`·`error` 를 받을 때마다 `say`·`ask`·`transfer`·`hangup` 중 **하나**를 보낸다 |
| **10초 안에** 답한다 | 넘기면 통화가 사람에게 간다(`app_error`). 업무 API 호출이 느리면 먼저 `say`(「확인하겠습니다」)로 시간을 번다 |
| **서명·타임스탬프를 확인**한다 | 틀리거나 ±300초를 벗어나면 연결을 받지 않는다 — 주소를 알아낸 제3자가 가짜 통화를 흘려 넣지 못하게 |
| 답이 정해진 질문은 **`choices` 를 함께** 보낸다 | DVG 가 답을 선택지로 읽어 준다(음성인식이 조금 틀려도 맞춰 읽는다) — `confirm:true`(추정한 답)면 **복창해 확인**받는다 |
| 생년월일은 **`expect:"birth"`** 로 묻는다(DVG 1.4.16.372+) | DVG 가 알아듣고 다음 물음을 준다 — `birth.question` 을 그대로 다시 묻고, `confirm`(다시 읽기)을 거쳐 `done` 에 원국 — 계약 §3-16 |
| 주소는 **`expect:"address"`** 로 묻는다 | DVG 가 시·도/구·군/동으로 풀어 준다. 여러 곳이면 `address.question` 을 **글자 그대로** 다시 묻는다(그래야 다음 답을 좁혀 준다) · 확정 전 **복창** — 계약 §3-5 |
| `ask` 는 **질문**, `say` 는 **안내** | `ask` 는 말하다가 발신자가 끼어들면 멈추고 답을 듣는다. `say` 는 끝까지 말한다 |
| **같은 질문을 되풀이하지 않는다** | 다시 물을 때는 **질문을 바꾼다** — 같은 문장 세 번은 발신자를 화나게 한다 |
| 예시·나열·복창은 **낱말마다 마침표로 끊는다** | ✅ 「선불. 착불. 결제는 어느 쪽인가요?」·「출발 강남역. 도착 서초동. 결제 착불.」 ❌ 「선불인지, 착불인지」·「선불인가요 착불인가요?」·「강원, 경남, 경북」 — 쉼표도 「~인지」도 전화에서 **한 덩어리로** 들린다. 🧪 시험이 그런 줄을 `toneWarning` 으로 짚는다 |
| 발신자를 탓하지 않는다 | ❌ 「잘 안 들리시네요」 ✅ 「제가 잘 못 들었습니다」 |
| 사람 연결 번호를 정하지 않는다 | `transfer` 는 운영사가 정한 번호로만 간다(통화료 사기 방지) |
| AI 고지를 하지 않는다 | DVG 가 앱보다 먼저 이미 했다(`setup.noticePlayed`) |
| `setup.simulated` 가 `true` 면 **실제 주문을 만들지 않는다** | 전화 없는 시험이다 |
| 가입자 조회는 **setup 을 받자마자** 시작하고 다 되면 첫 지시 | 걸려 온 통화의 setup 은 **벨 울리는 동안** 온다(`ringing:true` · 계약 §3-14) — 조회 시간이 벨 뒤에 숨는다 |
| 사람에게 넘기기 전 `setup.staff.handoffNotice` 가 있으면 붙여 말하기 | 근무 시간 밖이면 «바로 받지 못할 수 있어요 … 내일 오전 9시 이후에 연락드릴게요» — 발신자가 곧 연락이 오는 줄 오해하지 않는다(계약 §3-15) |
| 업무 API 토큰은 **캐시해서 재사용** · 만료 때만 다시 받는다 | 호출마다 받으면 느리고, «하나뿐인 토큰» API 는 서로를 끊는다 — [외부 API 자격증명](external-api-credentials.md) |

업무 시스템 API(주문 등록 등)는 **앱이 직접** 부릅니다 — DVG 는 중계하지 않습니다. `setup` 의 `orgId`(주문 회사)·`did`(걸려 온 번호)·`caller`(발신번호 — 운영사가 제공을 켠 경우만)로 판단하십시오.

⚠️ 업무 시스템 자격증명이 «하나에 토큰 하나» 방식이면 **다른 곳(운영사가 DVG 에 등록해 둔 것 포함)과 같은 자격증명을 쓰지 마십시오** — 서로의 토큰을 끊습니다. 앱 전용 자격증명을 받거나,
DVG 가 그 API 를 지원하면 운영사에 **토큰 중개**를 요청하십시오. 앱을 여러 대로 돌릴 때도 같은 문제가 생깁니다 — [외부 API 자격증명 · 토큰](external-api-credentials.md).

## 4. 시험하기

**전화 없이** — DVG 가 등록된 앱 주소로 **실제로 연결**해 실통화와 같은 흐름을 돌리고, 발신자의 말은 여러분이 적은 글로 대신합니다:

```bash
curl -sS -X POST -H "Authorization: Bearer $DVG_APP_KEY" -H 'Content-Type: application/json' -d '{"utterances":["강남역","","서초동","착불","네"]}' "https://<DVG 주소>/api/v1/apps/self/simulate"
```

- 빈 문자열은 «무응답» 입니다. 발화를 다 쓰면 «발신자가 끊음» 으로 끝납니다.
- 시험은 **사용량에 기록되지 않습니다** · 앱당 분당 20회.
- 🔊 AI 줄에 **`toneWarning`** 이 붙으면 그 문장은 예시가 붙어 들립니다(DVG 1.4.16.308+) — 예시마다 마침표로 끊으십시오. 실통화에서는 막지 않고 그대로 말합니다.
- ⚠️ **글자 시험입니다** — 음성인식 오인식·무음 판정·끼어들기는 재현하지 않습니다. 실통화의 `prompt.text` 는 「강남역**이요**」처럼 조사·군말이 붙어 옵니다.

**내 사용량**:

```bash
curl -sS -H "Authorization: Bearer $DVG_APP_KEY" "https://<DVG 주소>/api/v1/apps/self/usage?month=2026-09"
```

`found:false` 는 «0건» 이 아니라 **그 달에 아직 기록이 없다** 는 뜻입니다. 금액은 싣지 않습니다(수량만).

**내 통화 기록**(DVG 1.4.16.335+ · 대화 · 상담원 메모):

```bash
curl -sS -H "Authorization: Bearer $DVG_APP_KEY" "https://<DVG 주소>/api/v1/apps/self/diag?days=7"
```

운영사가 **«기록 공유»** 를 켠 회사의 통화만 옵니다(기본 꺼짐) — `sharedInstallations: 0` 이면 운영사에 요청하십시오. 자세한 필드는 [계약 §5-2](voice-relay-v1.md).

## 5. 체크리스트

- [ ] 서명·타임스탬프 검증(틀리면 연결 거절) — [시험 벡터](../conformance/vector.json) 통과
- [ ] 모든 메시지에 10초 안에 지시 하나
- [ ] 다시 물을 때는 질문을 바꾸고, 두 번 못 알아들으면 `transfer`
- [ ] 선택지 질문은 `choices` · `confirm:true` 면 복창 · 예시는 **낱말마다 마침표** · 🧪 시험에 `toneWarning` 이 **하나도 없다**
- [ ] 주소 질문은 `expect:"address"` · 여러 곳이면 DVG 의 `question` 을 그대로 · `verified:false` 면 반드시 복창 · 좌표가 필요하면 운영사에 «좌표 제공» 요청(없을 때의 처리도)
- [ ] `end` 를 받으면 그 통화 처리를 끝낸다
- [ ] `setup.simulated` 면 실제 주문을 만들지 않는다
- [ ] 업무 API 키는 환경변수(또는 비밀 저장소)에만 · 로그에 키·토큰·URL 쿼리를 남기지 않는다
- [ ] 업무 API 토큰을 캐시하고, 앱을 여러 대로 돌리면 [§4 의 방법](external-api-credentials.md#4-앱을-여러-대로-돌릴-때하나뿐인-토큰-api) 중 하나를 고른다
- [ ] 주문 등록은 재시도하지 않는다(또는 멱등 키) — 결과를 모르면 사람에게
- [ ] 로그에 발화·개인정보를 필요 이상 남기지 않는다(사이드카 로그는 운영사가 볼 수 있다)

- 앱이 사람 연결 번호를 지정하기 — 일부러 막았습니다
- 원시 오디오 스트림
- 운영사 관리 화면 안의 앱 화면
