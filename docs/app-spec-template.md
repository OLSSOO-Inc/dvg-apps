# 앱 명세서 양식

DVG 음성 앱을 **직접 만들든, AI 에게 만들게 하든** 이 양식부터 채우십시오. 코드를 쓰는 사람(또는 AI)이 짐작해야 하는 칸이 비어 있으면
그 자리에서 앱이 틀립니다. 이 파일을 복사해 `my-app-spec.md` 같은 이름으로 채우면 됩니다.

> ✍️ 칸마다 **예시**가 있습니다(꽃 배달). 지우고 여러분 업무로 바꾸십시오. 모르는 칸은 비워 두지 말고 «모름 — 운영사에 확인» 이라고 적으십시오.

---

## 1. 앱 개요

| 항목 | 적을 것 | 예시 |
|---|---|---|
| 앱 이름 | 운영사 화면에 보일 이름 | 꽃 배달 전화 주문 |
| 업무 | 한 문장 | 전화로 꽃 주문을 받아 우리 주문 시스템에 등록한다 |
| 전화 방향 | 걸려 오는 전화 / 우리가 거는 전화 / 둘 다 | 걸려 오는 전화 |
| 채팅 위젯에도 쓰나 | 예 / 아니요 — 예면 채팅에서는 **상담·안내만** 하고 주문은 사람에게 넘깁니다 | 아니요 |
| 첫 인사 | DVG 의 AI 고지 **다음에** 앱이 할 첫 문장 | 꽃 배달 주문을 도와드리겠습니다. |
| 끝 인사 | 접수가 끝나고 끊을 때 | 주문이 접수되었습니다. 감사합니다. |
| 사람에게 넘기기 직전 말 | `transfer` 바로 앞에 할 말(근무 시간 밖이면 DVG 의 `handoffNotice` 가 뒤에 붙습니다) | 담당자에게 연결해 드리겠습니다. |
| 기다리게 할 때 말 | 업무 API(고객 조회·등록 모두)가 느릴 때(3초 넘게) 먼저 할 말 — 10초 규칙 때문에 필요합니다 | 주문을 확인하고 있습니다. 잠시만 기다려 주세요. |
| 받지 않는 통화가 오면 | 위에서 «아니요» 라고 한 방향·채팅이 들어올 때 | 주문을 만들지 않고 사람에게 넘긴다 |

## 2. 받아야 할 칸 (순서대로)

한 줄이 한 칸입니다. **종류**는 넷 중 하나입니다.

- `주소` — DVG 가 시·도/구·군/동으로 풀어 줍니다
- `선택` — 답이 2~6개로 정해진 것(상품·결제·네/아니요)
- `전화번호` — 불러 주는 번호
- `자유` — 그 밖의 말(받는 분 이름·메모 등)

| 칸 이름(영문 키) | 종류 | 첫 질문 | 다시 물을 때(**첫 질문과 다른 문장**) | 선택지(선택일 때) | 복창할 때 앞말 | 필수? |
|---|---|---|---|---|---|---|
| `dest` | 주소 | 꽃을 어디로 보내 드릴까요? | 제가 잘 못 들었습니다. 받으실 곳의 구와 동을 말씀해 주세요. | — | 배달지 | 필수 |
| `product` | 선택 | 꽃다발. 꽃바구니. 화환. 어느 쪽으로 보내 드릴까요? | 제가 잘 못 들었습니다. 꽃다발이면 「꽃다발」. 화환이면 「화환」. | 꽃다발 · 꽃바구니 · 화환 | 상품 | 필수 |
| `receiver` | 자유 | 받으시는 분 성함을 말씀해 주세요. | 제가 잘 못 들었습니다. 받으시는 분 이름만 말씀해 주세요. | — | 받는 분 | 선택 |

### 2-1. 주소 칸 — 세부 처리

| 항목 | 적을 것 | 예시 |
|---|---|---|
| 주소 풀이를 못 쓰는 설치에서 | DVG 가 `address.status:"unavailable"` 을 주면 — **발화 원문을 그대로 받는다** / 다시 묻는다 | 발화 원문을 그대로 받는다(마지막 복창이 확인한다) |
| 장소·건물 이름(`address.name`) | 장례식장·병원 이름처럼 이름으로 찾았을 때 업무 API 의 **어느 칸**에 넣나 | `address.detail` 앞에 붙인다 |
| 동·호수만 들었을 때(`needsBuilding`) | 아파트·건물 이름을 한 번 묻나 · 물을 문장 · 들은 이름을 넣을 API 칸 | 묻는다 — 「아파트나 건물 이름을 말씀해 주시겠어요?」 · 장소 이름과 같은 칸 · 모르면 사람에게 |
| 일부만 들었을 때(`partial`) | 빠진 칸(`missing`)을 어떻게 묻나 | 「다시 물을 때」 문장으로 한 번 더 묻는다 |
| 이 칸을 최대 몇 번 묻나 | DVG 의 좁히는 질문까지 합친 상한 | 4번 — 넘으면 사람에게 |

✍️ 질문을 쓸 때 — 선택지는 **낱말마다 마침표**(「꽃다발. 꽃바구니. 화환.」), 물음은 **문장 끝에 한 번**, 발신자를 탓하는 말 금지.
자세한 규칙은 [AGENTS.md §2](../AGENTS.md#2-말투-규칙-전화로-들리는-모든-문장).

## 3. 확인과 등록

| 항목 | 적을 것 | 예시 |
|---|---|---|
| 마지막 복창 | 모은 칸을 어떻게 읽어 줄지 | 「배달지 서울 송파구 신천동. 상품 꽃바구니. 맞으면 「네」. 틀리면 「아니요」.」 |
| 「아니요」 라고 하면 | 사람에게 넘김 / 틀린 칸만 다시 묻기 | 사람에게 넘김 |
| 복창에 무응답·못 알아들은 답이면 | 한 번 바꿔 묻고 그래도면 사람에게 / 바로 사람에게 · 바꿔 물을 문장 | 한 번 바꿔 묻는다 — 「제가 잘 못 들었습니다. 주문 내용이 맞으면 「네」. 틀리면 「아니요」.」 · 그래도면 사람에게 |
| 등록할 곳 | 업무 시스템 API 이름과 문서 위치 | 우리 주문 API `POST /orders` (문서: 사내 위키 링크) |
| 인증 방식 | 고정 키 / 받을 때마다 새 토큰 / **새로 받으면 앞 토큰이 죽는 토큰** | 고정 키(`X-Api-Key`) |
| 보내는 값 | 칸 → API 필드 대응 | `dest` → `address.sido/gugun/dong/detail` · `product` → `item_code`(꽃다발=F1 · 꽃바구니=F2 · 화환=F3) · 발신번호 → `customer_phone` |
| 성공 판정 | 무엇을 받으면 성공인가 | HTTP 201 + 본문 `order_id` |
| 실패·모름 | 응답이 없거나 실패하면 | **재시도하지 않는다** · 사람에게 넘기고 메모에 «등록 결과 확인 필요» |
| 멱등 키 | API 가 중복 방지 키를 받는가 | 받지 않음 |
| API 주소 · 키를 담을 환경변수 이름 | 코드가 읽을 이름 — 값은 적지 마십시오 | `KKOT_API_BASE` · `KKOT_API_KEY` |
| 개발용 API | 시험 때 쓸 가짜·개발 서버(없으면 «AI 가 가짜 서버를 만든다») | AI 가 가짜 서버를 만든다(127.0.0.1) |

## 4. 사람에게 넘기는 경우

| 언제 | 상담원에게 남길 메모(`note`) |
|---|---|
| 같은 칸을 두 번 물어도 못 얻음 | 지금까지 모은 칸 + «○○ 칸을 못 들음» |
| 마지막 복창에서 「아니요」 | 모은 칸 전부 |
| 발신자가 «상담원» 을 찾음(아래 낱말) | 모은 칸 전부 |
| 등록 실패·결과 모름 | 모은 칸 + «등록 결과 확인 필요» |
| (업무에 맞게 추가) | |

| 상담원을 찾는 말로 볼 낱말 | 상담원 · 상담사 · 직원 연결 (「사람」·「직원」 한 낱말은 일반 답과 섞여 넣지 않는 편이 안전합니다) |

⚠️ 넘길 **번호는 적지 마십시오** — 운영사가 회사마다 정합니다. 부서가 여럿이면(예: 주문·민원) 부서 이름만 적고 운영사에 등록을 요청하십시오.

## 5. 업무 시스템에서 미리 알아야 하는 것

| 항목 | 적을 것 | 예시 |
|---|---|---|
| 발신번호로 고객 조회 | 하나? 어떤 API? 결과로 무엇을 건너뛰나 | `GET /customers?phone=` — 기존 고객이면 «지난번처럼 {지난 배달지}(으)로 보낼까요?» 를 먼저 묻는다(로/으로는 앱이 받침을 보고 고른다) |
| 고객 조회가 실패·늦으면 | 오류·시간 초과일 때 | 조회 결과 없음으로 보고 배달지를 처음부터 묻는다 |
| 발신번호가 꼭 필요한가 | 필요하면 운영사에 «발신번호 제공» 요청 | 필요 |
| 좌표가 필요한가 | 필요하면 «좌표 제공» 요청 · **없을 때의 처리** | 필요 없음 |
| 문자 안내 | 접수 후 통화 상대에게 보낼 문자(80바이트 이하) | 「꽃 주문 접수됨 {주문번호}」 |
| 문자가 80바이트를 넘으면 | 보내지 않는다 / 줄인 문장 | 보내지 않는다 |
| 회사마다 다른 값 | 운영사가 회사별로 넣을 설정 항목(키·이름·기본값) — **비밀번호는 넣지 않는다** | `shopName`(가게 이름 · 기본 「저희 꽃집」) |
| 근무 시간 밖 | 사람에게 넘길 때 안내를 덧붙이나 | 덧붙인다(DVG 의 `handoffNotice` 그대로) |

## 6. 음성인식 힌트 낱말

이 업무에서 자주 나오는 낱말(2~20자 · 60개까지) — **선택지 낱말 · 상품명 · 업계 용어**. 질문마다 바꿀 수 없고 앱 단위로 한 번 넣습니다(계약 §3-4).

예: 꽃다발 · 꽃바구니 · 화환 · 근조 · 축하 · 리본

## 7. 대화 예 (시험에 그대로 씁니다)

발신자가 할 말을 순서대로 적고, 첫 줄에 **기대 결말**(`completed` · `transferred` · `caller_hangup`)을 적습니다 — 로컬 점검의 `--expect` 에 그대로 넣습니다. 빈 줄은 «무응답» 입니다. **정상 · 무응답 · 못 알아들음 · 「아니요」** 네 가지는 꼭 적으십시오.

⚠️ 첫 예의 「서울이요」 는 DVG 가 «신천동이 여러 곳» 이라고 **좁혀 물었을 때**의 답입니다. 로컬 흉내 도구(`tools/local_dvg.py`)는 주소를 스스로 풀지 않으므로,
이런 예는 **DVG 가 줄 답을 함께 적은 발화 파일**로 돌립니다([예: 꽃 배달 좁히기](../tools/calls/flower-narrowed.json)) — 진짜 DVG 의 답인지는 운영사 DVG 의 `simulate` 로 확인하십시오.
⚠️ **주소를 못 알아듣는 예**(「어 그게」)도 마찬가지입니다 — DVG 답을 적지 않으면 흉내 도구가 «주소 풀이를 쓸 수 없는 설치» 로 답하고, 그때 원문을 받는 앱은 그 말을 배달지로 받습니다. 「주소로 읽지 못함」 을 적은 파일로 돌리십시오([예](../tools/calls/address-unknown.json)).
등록까지 시험할 예에는 «`--live`(개발용 API)» 라고 적고 **성공 · 실패 · 응답 없음** 세 가지를 모두 적으십시오.

```text
# 정상 → completed
신천동이요
서울이요
꽃바구니로 할게요
홍길동
네
```

```text
# 무응답 한 번 뒤 정상 → completed

송파구 신천동
화환
홍길동
네
```

```text
# 못 알아들음 두 번 → transferred (DVG 답 「주소로 읽지 못함」 을 적은 파일로)
어 그게
음
```

```text
# 마지막에 아니요 → transferred
송파구 신천동
꽃다발
홍길동
아니요
```
