# ☁️ 어디에 올릴까 — 플랫폼 고르기

[실서버 설치 퀵 가이드](deploy-quickstart.md)에는 **검증된 세 경로**(같은 서버 · 다른 서버 · Cloud Run)가 있습니다.
이 문서는 그 셋이 아닌 플랫폼을 쓰려 할 때 **먼저 읽을 것**입니다 — 무엇이 플랫폼을 가르는지, 어디가 되고 어디가 안 되는지.

> 📌 **이미 경로를 정하셨다면 이 문서가 필요 없습니다.** [퀵 가이드](deploy-quickstart.md)로 바로 가십시오.

## 1. 무엇이 플랫폼을 가르나

**DVG 가 여러분 앱에 접속합니다**(그 반대가 아닙니다). 통화 한 건은 **연결 하나**이고, 그 연결은 통화가 끝날 때까지 이어집니다.

```
전화 ──▶ DVG ──[WebSocket 연결 · 통화가 끝날 때까지]──▶ 여러분 앱
```

그래서 앱이 올라갈 곳은 셋을 갖춰야 합니다:

| # | 조건 | 왜 |
|---|---|---|
| 1 | **인터넷에서 닿는 주소**(또는 같은 서버의 루프백) | DVG 가 걸어야 합니다 |
| 2 | **WebSocket 연결을 받는 서버** | 요청 하나에 응답 하나가 아닙니다 |
| 3 | **연결을 통화 내내 유지** | 한 통화의 상한은 **10분**입니다([계약 §4](voice-relay-v1.md#4-결말과-상한)) |

🔴 **3번이 가릅니다.** 요청 하나를 받고 끝내는 구조(요청 단위로 과금·종료되는 서버리스 함수)는 맞지 않습니다.

⚠️ 10분은 **연결**의 상한이고, 한 **턴**의 상한은 **10초**입니다 — DVG 메시지 하나에 10초 안에 지시를 보내야 합니다.
업무 API 가 느리면 먼저 `say` 로 시간을 버십시오([계약 §2](voice-relay-v1.md)).

## 2. 어디에 올릴까

| 플랫폼 | 쓸 수 있나 | 어디를 보나 |
|---|---|---|
| **같은 서버**(사이드카) | ✅ **검증됨** | [퀵 가이드 **A**](deploy-quickstart.md#a-같은-서버--사이드카) |
| **다른 서버**(EC2 · VM · 오라클 등) | ✅ **검증됨** | [퀵 가이드 **B**](deploy-quickstart.md#b-다른-서버--nginx--systemd) |
| **Google Cloud Run** | ✅ **검증됨** | [퀵 가이드 **B2**](deploy-quickstart.md#b2-서버-없이--cloud-run) |
| **Fly.io** | 📄 **문서상 됨**(실측 전) | 🔴 자동 중지를 꺼야 합니다 — §4 |
| **Render** | 📄 **문서상 됨**(실측 전) | 무료 등급은 권하지 않습니다 — §5 |
| **Cloudflare 터널**(서버는 내 것) | 📄 **문서상 됨**(실측 전) | §3 |
| **AWS App Runner** | ⚠️ 권하지 않습니다 | WebSocket 지원이 확인되지 않습니다 — ECS Fargate + ALB 를 쓰십시오(그때는 퀵 가이드 **B** 와 같은 구성) |
| **AWS Lambda + API Gateway** | ⚠️ 예제를 그대로 쓸 수 없습니다 | 메시지마다 함수가 따로 불려 통화 상태를 밖(DB)에 둬야 합니다([퀵 가이드 맨 끝](deploy-quickstart.md)) |
| **Cloudflare Workers** | ⚠️ 권하지 않습니다 | 받는 쪽 WebSocket 에 Durable Objects 가 필요하고 예제를 그대로 쓸 수 없습니다 — 터널(§3)이 쉽습니다 |

> **표 읽는 법** — ✅ = **돌려 봤습니다** · 📄 = **공식 문서로 확인**했지만 **돌려 보지 않았습니다**(2026-10-19 기준) · ⚠️ = 권하지 않습니다.
> 플랫폼 정책은 바뀝니다. 어느 경로든 첫 배포 때 **🧪 시험**(§6)으로 확인하십시오.

## 3. Cloudflare 터널 — 서버는 내 것, 주소만 Cloudflare

> 📄 **Cloudflare 공식 문서 기준**입니다. 저희가 돌려 보지는 않았습니다.

고정 IP 가 없거나 들어오는 포트를 열 수 없을 때의 길입니다. **포트를 하나도 열지 않습니다.**

```bash
cloudflared tunnel login
```

```bash
cloudflared tunnel create dvg-app
```

```bash
cloudflared tunnel route dns dvg-app app.example.com
```

```bash
cloudflared tunnel run --url http://127.0.0.1:19999 dvg-app
```

relay 주소는 `wss://app.example.com/relay` 입니다(앱이 듣는 경로 그대로 — 예제 기본값은 `/relay`).

⚠️ **IP 로 막을 수 없습니다** — 퀵 가이드 **B** 의 nginx 허용 목록(`dvg-allow.conf`)에 해당하는 것이 터널에는 없습니다.
그때 **문은 앱의 서명 확인 하나**뿐이니, 서명·타임스탬프 검증을 **업그레이드 전에** 하고 있는지 확인하십시오([계약 §2](voice-relay-v1.md)).
Cloudflare Access 로 앞을 막는 방법은 DVG 가 그 인증을 하지 않으므로 **쓸 수 없습니다.**

⚠️ Cloudflare 가 자기 네트워크를 갱신할 때 연결이 끊길 수 있습니다. 끊긴 통화는 **사람에게 넘어갑니다**(통화를 잃지는 않습니다).

## 4. Fly.io

> 📄 **Fly 공식 문서 기준**입니다. 저희가 돌려 보지는 않았습니다.

```bash
fly launch --no-deploy
```

```bash
fly secrets set DVG_APP_SIGNING_SECRET='받은_서명_비밀'
```

⚠️ **작은따옴표로 감싸십시오** — 서명 비밀에 `$`·`!` 같은 글자가 있으면 셸이 먼저 해석해 **다른 값이 저장됩니다**(증상은 «붙었다가 바로 끊김»).
끝에 **줄바꿈이 붙지 않게** 하십시오(예제 앱이 앞뒤 공백을 지우지만, 비밀 저장소에 넣을 때 `echo` 대신 `printf` 를 쓰는 습관이 안전합니다).

```bash
fly deploy
```

relay 주소: `wss://내-앱-이름.fly.dev/relay`

### 4-1. 🔴 자동 중지를 끄십시오

Fly 프록시는 **들어오는 트래픽**을 보고 조용하면 머신을 멈춥니다. 통화 중 말이 없는 구간이 그렇게 보일 수 있습니다.
`fly.toml` 에:

```toml
[http_service]
  auto_stop_machines = "off"
  auto_start_machines = true
  min_machines_running = 1
```

⚠️ 공식 문서에 «열린 WebSocket 이 머신을 깨어 있게 한다»는 **명시가 없습니다.** 확인하기 전에는 꺼 두십시오.

## 5. Render

> 📄 **Render 공식 문서 기준**입니다. 저희가 돌려 보지는 않았습니다.

1. 대시보드 → **New → Web Service** → 저장소 연결
2. **Environment** 에 `DVG_APP_SIGNING_SECRET` 추가
3. relay 주소: `wss://내-앱-이름.onrender.com/relay`

🔴 **전화를 받는 앱이라면 유료 등급을 쓰십시오.** 무료 등급은 조용하면 잠들고, **깨어나는 데 약 1분**이 걸립니다 —
DVG 는 앱 연결을 **수 초**만 기다리므로 그 통화는 `app_unavailable` 로 사람에게 넘어갑니다.

## 6. 어느 플랫폼이든 — 올리고 나서

### 6-1. 전화 없이 확인

```bash
curl -sS -X POST -H "Authorization: Bearer dvga_받은-앱-키" -H 'Content-Type: application/json' -d '{"utterances":["안녕하세요"]}' "https://DVG-주소/api/v1/apps/self/simulate"
```

이것은 흉내가 아닙니다 — **등록된 주소로 서명된 연결을 실제로 걸어** 실통화와 같은 흐름을 돌립니다.
사용법과 relay 주소 바꾸기는 [시작하기 §4](getting-started.md#4-시험하기) · [계약 §5](voice-relay-v1.md) 에 있습니다.

| 보이는 것 | 뜻 | 할 일 |
|---|---|---|
| 대화가 글자로 돌아옴 | ✅ 연결·서명·대화 모두 정상 | 끝 |
| `app_unavailable` | 연결 자체가 안 됨 | 주소가 `wss://` 인지 · 경로 · 방화벽 · 잠든 인스턴스(§5) |
| 붙었다 바로 끊김 | **서명 불일치** | 서명 비밀에 **줄바꿈·공백**이 붙지 않았는지 · 서버 시계(NTP — 서명은 ±300초) |
| 통화 중간에 끊김 | 연결 유지 시간 | 플랫폼의 유휴·연결 상한(§4 · §5) |
| 첫 통화만 느림 | 인스턴스가 자고 있었음 | 한 대는 깨워 두십시오 |

### 6-2. 올리기 전 체크리스트

- [ ] 서명 비밀이 **코드·깃에 없다**(환경변수·비밀 저장소에만)
- [ ] 주소가 **`wss://`** 다(`ws://` 는 같은 서버일 때만)
- [ ] **연결이 10분을 버틴다** — 한 통화의 상한입니다
- [ ] 한 턴을 **10초** 안에 돌려준다 — 느린 업무 API 는 `say` 로 시간을 번다
- [ ] 쉬고 있어도 **첫 연결이 수 초 안에** 붙는다
- [ ] 앱이 죽어도 **다시 뜬다**
- [ ] 서버 **시계가 맞다**(NTP)
- [ ] `simulate` 가 끝까지 통과한다(§6-1)

## 7. 아직 확인하지 못한 것

- **Fly.io · Render · Cloudflare 터널**은 **공식 문서로 확인**했고(2026-10-19) 되는 것으로 보이지만
  **저희가 실제로 배포해 보지는 않았습니다** — 그래서 ✅ 가 아니라 📄 입니다.
- **AWS** 는 EC2·ECS 로는 퀵 가이드 **B** 와 같지만 **App Runner·Lambda 는 권하지 않습니다**(§2).
- 이 문서의 명령은 **형식만 확인**했습니다. 첫 배포 때 반드시 `simulate`(§6-1)로 확인하십시오.

돌려 보신 결과를 [이슈](https://github.com/OLSSOO-Inc/dvg-apps/issues)로 알려 주시면 📄 를 ✅ 로 바꾸겠습니다.
