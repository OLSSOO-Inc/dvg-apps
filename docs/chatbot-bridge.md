# 챗봇 연결 — 이미 있는 AI 채팅을 DVG 전화·웹 채팅에 붙이기

> 대상: **이미 AI 채팅(챗봇)을 운영하는 회사**. **DVG 1.4.17.68 이상**.
> 이 경우 DVG 앱([계약 v1](voice-relay-v1.md))을 새로 만들 필요가 없습니다 — 운영사가 «챗봇 연결» 앱에
> 여러분의 챗봇 주소를 넣으면, 그 앱이 계약을 대신 말합니다. **여러분이 만드는 것은 챗봇 쪽 주소 하나**입니다.

```
손님 ──전화·채팅──▶ DVG ──▶ 챗봇 연결 앱 ──HTTP──▶ 여러분의 챗봇
                   음성인식·음성합성         말을 옮김          답을 만든다
                   AI 고지·사람 연결         전화용 말투 다듬기
```

## 0. 어느 길을 고르나

| 상황 | 길 |
|---|---|
| 챗봇이 이미 있고 **그대로** 전화·채팅에 붙이고 싶다 | **이 문서** — OpenAI 호환 주소를 주거나(§3), 작은 웹훅을 만든다(§4) |
| 대화 흐름(무엇을 묻고 언제 복창할지)을 **직접** 짜고 싶다 · 주소·생년월일·날짜를 DVG 가 풀어 주길 원한다 | [앱 계약 v1](voice-relay-v1.md)로 앱을 만든다 |
| 챗봇이 대화 중에 **발신·문자 같은 동작**을 하게 하고 싶다 | 운영사에 MCP 도구 연결을 문의한다(대화 자체를 실어 나르는 길은 아니다) |

⚠️ 챗봇 연결은 **말을 옮기는 일만** 합니다. 주소·생년월일 풀이, 선택지 판정 같은 DVG 기능을 대화 흐름에 쓰려면 앱 계약 쪽이 맞습니다.

## 1. 누가 무엇을 하나

| 운영사(DVG 관리자) | 챗봇을 가진 회사 |
|---|---|
| «챗봇 연결» 앱 등록·회사 설치·켜기 | 챗봇 주소 하나 — OpenAI 호환(§3) 또는 웹훅(§4) |
| 챗봇 주소·키·서명 비밀·모델 이름을 앱 설정에 넣기 | 그 값을 운영사에 전달(키는 비밀 통로로) |
| 첫 인사 · 사람 연결 번호 · 상담원 근무 시간 · 부서 | 사람에게 넘길 때·끝낼 때를 챗봇이 정하기 |
| AI 고지(DVG 가 먼저 말한다 · 끌 수 없다) | 전화에 맞는 답(§5) |
| 응답 상한 시간 · 대화 길이 상한 | 응답 시간 줄이기 — 전화에서는 그 시간이 **무음**이다 |

## 2. 운영사에 보낼 것

- **방식**: `openai` 또는 `webhook`
- **주소**: `https://…` — OpenAI 호환이면 **`/chat/completions` 까지 전체 주소**
- **키**(있으면): `Authorization: Bearer …` 로 보냅니다
- **서명 비밀**(웹훅 · 권장): §4-3
- **모델 이름**(OpenAI 호환 · 필요하면) · **챗봇에 붙일 지시문**(원시 LLM 을 쓸 때만 — 여러분 서버가 이미 지시를 갖고 있으면 비웁니다)
- 채팅에서도 쓸지 · 회사별 첫 인사
- DVG 서버의 공인 IP 를 받아 **여러분 쪽 방화벽**에 열어 두십시오

⚠️ `http://` 주소는 손님 말과 키가 암호화 없이 나갑니다 — 같은 서버나 사내망이 아니면 `https://` 를 쓰십시오.

## 3. OpenAI 호환 방식

`/chat/completions` 를 받는 서버(OpenAI · Ollama · vLLM · LiteLLM · 사내 프록시 등)면 **코드 없이** 됩니다.

### 3-1. 보내는 것

```json
{
  "model": "운영사가 넣은 모델 이름(없으면 이 칸이 없다)",
  "stream": false,
  "messages": [
    {"role": "system", "content": "회사 지시문 + 전화/채팅 말투 지시 + 도구 안내"},
    {"role": "user", "content": "주차 어디예요?"},
    {"role": "assistant", "content": "건물 지하 2층이에요. 더 궁금하신 점이 있을까요?"},
    {"role": "user", "content": "예약 바꾸고 싶어요"}
  ],
  "tools": [ … transfer_to_human · end_conversation … ],
  "tool_choice": "auto"
}
```

- `messages` 는 **최근 20줄**(방금 손님 말 포함 · 한 줄 1,000자)입니다. 여러분 서버는 상태를 갖지 않아도 됩니다.
- **회사 정보**(DVG 1.4.17.72 이상) — 운영사가 회사 기본정보(상호·전화·주소·주차·운영 시간 …)를 적었으면 «이 값만 근거로 답하고 없는 정보는 지어내지 말라» 는 지시와 함께 시스템 메시지에 붙습니다. 적은 칸만 · 없으면 붙지 않습니다.
- **말투 지시**(운영사가 끌 수 있음) — 전화면 «한두 문장 · 마크다운·목록·표·이모지·링크 주소 금지 · 쉼표 대신 마침표 · 예시는 낱말마다 마침표 · 물음은 끝에 한 번», 채팅이면 «짧게 · 마크다운 기호 금지 · 링크는 주소 하나».
- `max_tokens` 는 운영사가 정했을 때만 보냅니다(최신 모델 일부는 이 이름을 거절합니다).

### 3-2. 도구 두 개 — 사람 연결·끝내기

| 도구 | 인자 | DVG 가 하는 일 |
|---|---|---|
| `transfer_to_human` | `department`(회사에 부서가 있을 때만 · 그 key 중 하나) · `note`(상담원에게 전할 한두 문장) | `content` 가 있으면 말하고 사람(또는 부서)에게 넘긴다 |
| `end_conversation` | 없음 | `content`(마지막 인사)를 말하고 끝낸다 |

- 둘 다 오면 **사람 연결이 이깁니다.** 모르는 부서 key 는 회사의 사람 연결 번호로 갑니다.
- 🔴 **도구를 모르는 서버가 많습니다.** 도구를 실어 **HTTP 400** 이 오면 도구 없이 **한 번** 다시 묻고, 그 뒤로는 싣지 않습니다. 그때 사람 연결은 §5-3 의 «상담원» 판정으로만 됩니다.

### 3-3. 받는 것

`choices[0].message.content`(글)와 `tool_calls` 만 봅니다. `content` 가 비고 도구도 없으면 실패로 봅니다(§6).

⚠️ **Azure OpenAI 는 직접 안 됩니다** — 키를 `api-key` 헤더로 받습니다. LiteLLM 같은 프록시를 앞에 두거나 웹훅 방식을 쓰십시오.

## 4. 웹훅 방식

여러분 서버가 아래 JSON 을 받아 답합니다(n8n · Flowise · 사내 API). 표준 라이브러리만 쓰는 예제가 [`examples/chatbot-webhook/`](../examples/chatbot-webhook/) 에 있습니다.

### 4-1. 요청 — `POST` · `application/json`

```json
{
  "version": 1,
  "event": "message",
  "conversationId": "1792843529.123",
  "channel": "phone",
  "text": "예약 취소하려고요",
  "choice": "",
  "history": [
    {"role": "assistant", "text": "안녕하세요. 무엇을 도와드릴까요?"},
    {"role": "user", "text": "예약 취소하려고요"}
  ],
  "caller": "01012345678",
  "did": "07012345678",
  "tenantId": "…",
  "orgId": "…",
  "simulated": false,
  "departments": [{"key": "d00000001", "name": "예약실"}],
  "company": {"name": "예시 치과", "phone": "02-1234-5678", "parking": "건물 지하 2층에 주차하실 수 있습니다."},
  "ts": 1792843529
}
```

| 필드 | 뜻 |
|---|---|
| `event` | `start`(대화 시작) · `message`(손님이 말함) · `end`(끝남) |
| `conversationId` | 통화(또는 채팅) 하나의 식별자 — 상태를 가진 서버는 이것으로 묶는다 |
| `channel` | `phone` · `chat` — 전화면 짧게(§5) |
| `text` | 방금 손님 말(`message` 일 때) |
| `choice` | 앞 답에 `choices` 를 줬고 손님 말이 그중 하나로 맞춰졌을 때 그 값 |
| `history` | 최근 20줄(방금 손님 말 포함) — **상태 없는 서버도 된다** · 챗봇 답은 다듬기 **전** 원문 |
| `caller` | 🔒 운영사가 그 설치에 **발신번호 제공**을 켰을 때만 있다(그 밖에는 키 자체가 없다) · 채팅에는 없다 |
| `simulated` | `true` 면 **전화 없는 시험** — 실제 예약·주문·결제를 만들지 마십시오 |
| `departments` | 회사에 등록된 부서(key·이름 · **번호 없음**) |
| `company` | 운영사가 적은 회사 기본정보(`name`·`bizNo`·`phone`·`fax`·`email`·`postalCode`·`address`·`website`·`mapUrl`·`parking`·`directions`·`hours` · DVG 1.4.17.72 이상) — **적은 칸만** · 없으면 키가 없다 · 주차·영업시간·주소 물음은 이 값을 근거로 답하면 된다 |
| `reason` | `end` 일 때만 — 아래 표 |
| `ts` | 보낸 시각(유닉스 초) — 재전송 막기에 쓴다 |

`end` 의 `reason`: `transfer:bot`(챗봇이 넘김) · `transfer:asked`(손님이 상담원을 찾음) · `transfer:bot_error`(챗봇 호출 실패) · `transfer:empty`(챗봇이 빈 답) · `transfer:silence`(무응답) · `transfer:turns`(대화 상한) · `hangup` · `ended`(손님이 먼저 끊음) · `error`.

### 4-2. 응답 — `2xx` · `application/json`

```json
{
  "reply": "예약을 취소할까요?",
  "action": "continue",
  "department": "",
  "note": "",
  "link": {"label": "예약 확인", "url": "https://example.com/booking"},
  "choices": ["네", "아니요"]
}
```

| 필드 | 뜻 |
|---|---|
| `reply` | 손님에게 할 말 |
| `action` | `continue`(기본 · 비거나 모르는 값도) · `transfer`(사람·부서에게) · `hangup`(말하고 끝냄) |
| `department` | `transfer` 의 부서 key — 요청의 `departments` 에 없으면 회사의 사람 연결 번호로 간다 |
| `note` | 상담원 메모 — 상담원에게 넘어가는 기록에 남는다 |
| `link` | 채팅에서 말풍선 아래 버튼(https · 이름 20자 이하 · 주소 500자 이하) · 전화는 무시 |
| `choices` | 다음 물음의 선택지 2~6개(각 20자 이하 · 중복 없음) — 규칙에 안 맞으면 통째로 빼고 보낸다 |

- `start` 에 `reply` 를 주면 그것이 **첫 인사**입니다(비우면 운영사가 정한 인사). `start` 에 `transfer`·`hangup` 도 됩니다.
- `end` 의 응답은 쓰이지 않습니다(3초 상한 · 실패해도 무시) — 상태를 지우는 자리입니다.
- `continue` 인데 `reply` 가 비면 실패로 봅니다(§6). 응답 본문은 1MB 이하.

### 4-3. 서명 확인 (권장)

서명 비밀이 있으면 `X-DVG-Signature: hex(HMAC-SHA256(비밀, 본문 바이트))` 를 붙입니다. 키가 있으면 `Authorization: Bearer {키}` 도 붙습니다.

```python
import hmac, hashlib

def verify(secret: bytes, raw_body: bytes, header: str) -> bool:
    want = hmac.new(secret, raw_body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(want, header or "")
```

- ⚠️ **본문을 파싱하기 전의 바이트**로 계산하십시오(JSON 을 다시 만들면 맞지 않습니다).
- 시험 벡터: 비밀 `whsec` · 본문 `{"version":1,"event":"message"}` → `3d2a77c9bf41b413af1634205fd6ec52615bc8a15d5f0c4c7239082f4da20e79`
- 틀리면 **401** 로 거절하십시오. 재전송 막기에는 `ts`(예: ±300초)를 보십시오.

## 5. 전화에 맞추기

### 5-1. 자동으로 하는 것 (전화)

| 챗봇 답 | 전화로 읽는 말 |
|---|---|
| `**주차**는 지하예요 😊` | 주차는 지하예요. |
| `- 지하 2층`<br>`- 2시간 무료` | 지하 2층. 2시간 무료. |
| `네, 알겠습니다` | 네. 알겠습니다.(한글 뒤 쉼표 → 마침표 · 「1,000원」은 그대로) |
| `[요금표](https://…)를 보세요` | 요금표를 보세요. |
| `자세한 건 https://… 참고` | (그 문장을 뺀다 — 전화로는 쓸 수 없다) |
| 300자 넘는 답 | 300자 안의 마지막 문장 끝에서 자른다 |

채팅에서는 답 속의 첫 https 주소를 🔗 버튼으로도 보여 줍니다(`link` 를 주면 그것이 먼저).

### 5-2. 챗봇이 맞춰야 하는 것

DVG 는 문장을 다시 쓰지 않습니다. 아래는 여러분 챗봇이 맞춰야 합니다(전화에서 실제로 문제가 난 모양들입니다):

| ✅ | ❌ | 왜 |
|---|---|---|
| 「주차는 지하 2층이에요. 더 궁금하신 점이 있을까요?」 | 「더 궁금하세요? 주차는 지하예요.」 | 물음이 앞에 있으면 손님이 거기서 대답을 시작하고 뒷말을 못 듣는다 |
| 「월요일. 수요일. 금요일. 어느 날이 좋으세요?」 | 「월요일, 수요일, 금요일 중에」 | 쉼표로 늘어놓으면 붙어 들린다 |
| 한두 문장 | 채팅용 긴 문단 | 길면 손님이 중간에 놓친다 |
| 「제가 잘 못 들었어요.」 | 「또박또박 말씀해 주세요.」 | 손님 탓으로 들린다 |
| 손님이 고른 답이 오면 다음으로 | 같은 질문을 다시 | 같은 질문 반복은 손님을 화나게 한다 |

`channel` 이 `phone` 일 때만 짧게 답하도록 분기하면 채팅 답은 그대로 둘 수 있습니다.

### 5-3. 사람 연결

- 챗봇이 정합니다(`transfer_to_human` · `action:"transfer"`).
- 그와 별개로 손님이 **«상담원»·«상담사»** 를 부르거나 **«사람·직원·담당자 + 연결·바꿔·통화»** 를 말하면 **챗봇에 묻지 않고** 바로 넘깁니다(«상담원 말고»·«필요 없어요» 같은 거절은 제외). 운영사가 끌 수 있습니다.
- 넘길 때 상담원 메모에 챗봇의 `note` · 넘긴 이유 · 손님 마지막 말(120자)이 실립니다.

## 6. 실패·무음·상한

| 상황 | 하는 일 |
|---|---|
| 챗봇 호출 실패(시간 초과·연결 실패·2xx 아님·JSON 아님) | 「지금은 답변을 준비하지 못했어요. 담당자에게 연결해 드릴게요.」 → 사람에게 · **다시 부르지 않는다** |
| 챗봇이 빈 답 | 같은 말 → 사람에게 |
| 전화 무응답 1번 → 2번 | 다른 말로 한 번 다시 묻고 → 사람에게(무응답은 챗봇에 보내지 않는다) |
| 채팅 무응답 1번 → 2번 | 한 번 권하고 → 끝인사 |
| 손님 말이 대화 상한(기본 20)을 넘음 | 「더 자세한 내용은 담당자가 안내해 드릴게요.」 → 사람에게 |
| 상담원 근무 시간 밖에 넘김 | 넘기는 말 뒤에 근무 시간 안내를 덧붙인다 |

응답 상한은 기본 **8초**(운영사가 1~60초로 정함)입니다.

   ```bash
   CHATBOT_WEBHOOK_SECRET=… python3 examples/chatbot-webhook/webhook_bot.py
   ```

2. 운영사가 등록을 마치면 운영사 대시보드의 **🧪 시험**으로 전화 없이 같은 대화를 돌려 봅니다(`simulated:true` 로 옵니다).
3. 마지막으로 실제 전화 한 통 · 실제 채팅 한 번.

## 8. 비용과 지연

- 💰 챗봇 호출 비용은 여러분 몫이고, 음성인식·음성합성은 DVG 쪽 비용입니다. 챗봇 호출 수 = 손님 말 수(+ 웹훅의 `start`·`end` 각 1회 · OpenAI 호환은 시작·끝 호출 없음).
- ⏱ **전화에서는 챗봇 응답 시간이 그대로 무음입니다.** 2~5초 걸리면 손님은 그만큼 기다립니다 — 빠른 모델·짧은 답을 고르십시오.

## 9. 한계

- 앱 계약의 기능(주소·생년월일·날짜 풀이 · 문자 보내기 · 긴 듣기)은 챗봇 연결에서 쓸 수 없습니다 — 필요하면 [앱 계약](voice-relay-v1.md)으로 앱을 만드십시오.
- 스트리밍 응답(`stream:true`)은 쓰지 않습니다 — 답 전체가 온 뒤 말합니다.
